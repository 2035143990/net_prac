## 1 开场：项目概况、系统细节与技术栈（约 2 分钟）

**讲：** 我们做的是奉贤校区校园网，覆盖教学、实验、宿舍、图书馆、生活和信息大楼六个区域，信息点约一万四千五百个。主干一万兆，从网络中心到各区域汇聚；汇聚到楼层一千兆；宿舍房间一百兆，其他房间一千兆。

**讲：** 架构是三层。信息大楼机房放两台核心交换机，两台之间用两条万兆线绑成一条；每个区域放两台汇聚，分别上联两台核心；接入交换机按楼宇放，每栋楼每一层一台。出口是两台路由加两台防火墙，防火墙分内网、外网和对外服务区三块，对外服务的网站单独挂在服务区。

**讲：** 地址规划的原则是一栋楼一个子网。按这个原则算下来，教学楼五栋、实验楼八栋、学生公寓二十八栋，加上图书馆、食堂两栋、体育馆，一共四十四栋楼；再加上数据中心、对外服务区和两个无线网段，业务网段一共四十九个，另外单独划一个管理网段给网络设备用，合起来正好五十个。仿真环境只取代表性楼栋，实际部署了十一个。预算按规模留三成余量，合计约六百八十七万。

## 2 仿真怎么用 Docker 搭起来（约 1.5 分钟）

**讲：** 仿真不是真买四十九台设备，而是在一台笔记本上开四十九个容器，一个容器就是一台设备。每个容器里只装这台设备需要的软件，所以一台笔记本就能扛住整张网，而且可以反复重建、随时销毁。

**讲：** 设备分四类，对应四个自己做的镜像。路由镜像装路由协议、虚拟网关、防火墙规则和地址服务，十四台；二层镜像做 VLAN 交换，七台；防火墙镜像做包过滤和会话跟踪，两台；主机镜像放终端、服务器和无线接入点，二十台；另有六台传输桥把出口各段连起来。

**讲：** 拓扑和配置不是手写的。一份 Python 脚本按事实源生成拓扑描述、每台设备的配置目录和地址表，容器启动时把各自的配置挂进去。设备之间的网线由实验平台自动创建，是一对虚拟网卡，一共七十二条。

**讲：** 部署分三步：构建四个镜像、生成拓扑和配置、一条命令起全部容器。苹果电脑上要套一层包装脚本，把容器网络挂到主机上，否则虚拟网线挂不进容器。销毁也是一条命令，容器和链路一起清掉。

```sh
# 1. 四个本地镜像，构建一次反复用
docker image ls --filter reference='campus-*' --format '{{.Repository}}:{{.Tag}}  {{.Size}}'

# 2. 容器名单，镜像名就是设备角色
docker ps --filter name=clab-campus-lab- --format '{{.Names}}  {{.Image}}' | head -10

# 3. 进一教的汇聚，看网卡和进程，与真机排障一样
docker exec clab-campus-lab-agg-t1 ip -br link
docker exec clab-campus-lab-agg-t1 ps | head
```

**说：** 每个容器都能进去看网卡、看进程、看路由表；局限是不模拟端口密度、光模块和供电，这些在真实采购时再落实。

### Q4 是否全部能 Ping 通？

必须分两类回答：

1. **应当可达的**：CONN-01~10 全部通过
   - CONN-01 VLAN101 同网段互通
   - CONN-02 VLAN101 → VLAN102 三层互通
   - CONN-03 教学区 → 实验区 VLAN201
   - CONN-04 教学区 → 宿舍区 VLAN301
   - CONN-05 教学区 → 图书馆 VLAN50
   - CONN-06 教学区 → 生活区 VLAN61
   - CONN-07 教学区 → 数据中心 VLAN70
   - CONN-08 有线 → 无线 VLAN500
   - CONN-09 内网经 NAT 访问 Internet
   - CONN-10 内网访问 DMZ 服务器
2. **应当不可达的**：ISO 套件专门验证「不通」，这些不通才是正确结果
   - 宿舍 → 管理网 / 教学区 / 实验区 / 数据中心 阻断
   - 教学区 → 管理网 阻断
   - 教学区 → 宿舍区 阻断
   - 宿舍 → 图书馆 默认拒绝
   - DMZ → 内网、外网 → Trust、外网 → 宿舍区 失败

结论表述：最终全量 **85/85 全部通过**（run-id `20261111T145644Z`），0 失败 0 跳过；期间定位并修复 19 类实现缺陷（含 FRR 节点 keepalived 未启动、keepalived 配置权限、CONN-04 断言与访问控制矩阵矛盾、仓库 CRLF 行尾、VLAN 510 汇聚层桥接环路、梅陇网段被聚合路由吞掉、`facts.json` 跨平台编码不一致），均已归档在 `docs/verification-report.md`。

### Q9 有没有防火墙？

有，双机 fw1/fw2，使用 nftables 落地三区策略。

| 区域 | 连接 | 默认策略 |
| --- | --- | --- |
| Trust | 核心、全部校内 VLAN | 可访问 Untrust、DMZ |
| Untrust | Internet、梅陇校区 | 默认拒绝，仅放行命中 DNAT 的 80/443 |
| DMZ | Web、邮件、对外 DNS、VPN | 外网只可达指定端口，DMZ 不可主动访问内网 |

细节：
- DNAT：`198.51.100.80:80/443 → 10.80.0.10`，只允许 `ct status dnat` 流量；
- SNAT：仅 `iifname eth1 oifname eth2` 做 masquerade，避免改写 DNAT 回程；
- 管理口不对公网开放；
- SEC-01~06、NAT-01~07 全部通过。

### Q12 是否考虑了网络的可扩展性、安全性、绿色环保？

**可扩展性**
- 区域汇总路由：核心只看见区域汇总，看不见单栋楼，减少路由表规模；
- 地址规划「地址即含义」：`10.A.B.0/24` 中 A 表示区域、B 表示楼栋，可平移扩展；
- IPv6 双栈预留，本期只规划 IPv4；
- 设备按 5–10 年、留 30% 余量选型。

**安全性**
- 出口三区防火墙 + NAT + 只开指定端口；
- 宿舍区细粒度 ACL：宿舍只能互访、DNS、Internet、DMZ 80/443，其余默认拒绝；
- 管理网独立 VLAN 90，业务区不可达；
- 802.1X / Portal + RADIUS，MAC/IP 绑定；
- DHCP Snooping、DAI、端口隔离、端口安全、未用端口 shutdown；
- 设备侧 SSH v2、SNMPv3、关闭 Telnet。

**绿色环保**
- 选高能效设备型号；
- PoE 按 AP 实际功率（约 15W/台）选型，宿舍百兆口不配 PoE+；
- 机房精密空调 + 冷热通道；
- 统一网管减少现场巡检能耗。

## 3 实验一：教学区交换与无线（约 1 分钟）

**讲：** 一教每一层一台接入交换机，教室端口划在教学子网，无线单独一个子网。上联到一教的汇聚走 trunk，网关放在汇聚上，所以同一栋楼内是二层转发，跨楼才经过汇聚做三层转发。无线是统一控制器加瘦接入点，每栋楼每层一个，全校二百八十七个。

```sh
# 一教教室两台电脑互 ping
docker exec clab-campus-lab-pc-ta1 ping -c 2 10.10.0.12

# 一教有线电脑访问本楼无线接入点
docker exec clab-campus-lab-pc-ta1 ping -c 2 10.50.0.11
```

## 4 实验二：地址服务（约 1 分钟）

**讲：** 地址服务集中在信息大楼数据中心，一共八个动态地址池，教学、实验、宿舍、图书馆、生活区和两个无线各一个。十台区域汇聚做中继，把各楼的需求转给服务器。租期按区域区分：教学四小时，宿舍十二小时，其他八小时。下发的网关是虚拟地址，主备切换时电脑不用改配置。

```sh
# 一教演示电脑拿到的地址、网关、域名服务和租期
docker exec clab-campus-lab-pc-dyn1 cat /tmp/dhcp.env
```

**说：** 这台电脑拿到教学子网地址，网关是一教汇聚的虚拟地址，域名服务指向信息大楼，租期四小时。

## 5 实验三：冗余与出口安全（约 2 分钟）

**讲：** 冗余分四层。核心两台做虚拟网关，主用坏了备用接管；防火墙两台同样做虚拟网关；出口两台路由，一台主用教育网，一台备用运营商并兼连梅陇校区；链路层面，两台核心之间是双线聚合，数据中心服务器是双网卡主备。

**讲：** 出口安全统一收在防火墙上。内网出去做源地址转换，外面看到的是出口地址；外面进来只能访问对外服务区的网站，八十和四百四十三端口，内网地址外面碰不到。

```sh
# 看出口会话，内网源地址已被改写成防火墙外网口
docker exec clab-campus-lab-fw1 conntrack -L | grep 203.0.113.100 | head -3
```

```sh
# 先持续 ping 校外，再停掉信息大楼机房的主核心
docker exec clab-campus-lab-pc-dyn1 ping -c 30 -i 0.5 203.0.113.100 &
docker stop clab-campus-lab-core1
sleep 5
docker start clab-campus-lab-core1
```

**说：** ping 没断，备用核心接管了虚拟网关，恢复后主核心重新抢回。唯一单点是信息大楼那台地址与域名服务器，目前只有一台在跑，备机建了但没启用，这点我们如实说明。

## 6 实验四：路由与链路聚合（约 1 分钟）

**讲：** 内网跑开放最短路径优先协议，所有区域在一个骨干域里。核心向区域下发默认路由，区域只把汇总网段告诉核心，所以核心路由表不膨胀。两台核心之间的双线聚合成一条逻辑链路，带宽翻倍，一条线断业务不断。

```sh
# 一教电脑到校外的完整路径
docker exec clab-campus-lab-pc-dyn1 traceroute -n -w 1 -q 1 -m 8 203.0.113.100

# 核心邻居数量与聚合口状态
docker exec clab-campus-lab-core1 vtysh -c 'show ip ospf neighbor' | grep -c Full
docker exec clab-campus-lab-core1 cat /proc/net/bonding/bond0 | head -8
```

**说：** 从一教出去是五跳：楼层接入、一教汇聚、信息大楼核心、出口防火墙、出口路由，然后到校外。信息大楼核心看到十一条邻居，聚合口两条成员都在线。

## 7 实验五：区域隔离与自动化验收（约 2 分钟）

**讲：** 区域之间不经过防火墙，隔离做在区域汇聚上。宿舍六个方向全阻断：管理网、教学、实验、数据中心都进不去，只放行宿舍互访、域名服务、出网和对外服务区网站；生活区只放行出网和对外服务区，其他六个方向全拒绝；数据中心禁止主动出校；管理网只允许网管终端发起。

```sh
# 食堂电脑访问一教：应不通
docker exec clab-campus-lab-pc-life ping -c 2 -W 1 10.10.0.11

# 食堂电脑访问校外：应通
docker exec clab-campus-lab-pc-life ping -c 2 -W 1 203.0.113.100
```

**讲：** 验收是八个套件、六十四条用例，覆盖连通、路由、安全、地址服务、隔离、地址转换、链路聚合和故障切换。第一次跑了六十一分，三条失败定位到管理流量回程不对称和路由恢复等待窗口，修复以后全量六十四分全过，没有失败也没有跳过。测试开始前会先等核心把十一条邻居收齐，避免刚部署就判失败。

## 9 边界与收束（约 1 分钟）

**讲：** 三点边界主动交代。第一，跨校区已建模但只建到网段级：梅陇侧建了对端网关和一台业务主机，完整徐汇校区的楼宇设备没有展开。第二，文件传输服务本期没部署，对外服务区具备承载能力，列在后续工作。第三，地址和域名服务目前单实例。

**讲：** 无线这边仿真只验证了子网、地址池和认证策略，天线覆盖要到真实环境勘测；域名内外分设和八零二点一叉认证是设计内容，仿真没建模。

**说：** 一句话收尾：设计成体系、实现能跑通、结果可复核。
