## 2 逐条答辩口径

### Q1 奉贤校区划分了几个区？

6 大功能区：

| 区域 | 构成 | 汇聚方式 |
| --- | --- | --- |
| 教学区 | 教学楼 A–E（5 栋，4 层） | 教学 A 楼汇聚，双 10G 上核心 |
| 实验区 | 实验楼 A–H（8 栋，8 层） | 实验 A 楼汇聚，双 10G 上核心 |
| 宿舍区 | 学生公寓 1–28（28 栋，6 层） | 第 1 宿舍汇聚，双 10G 上核心 |
| 图书馆 | 图书馆 1 栋 10 层 | 独立汇聚，10G 上核心 |
| 生活区 | 食堂 1–2 + 体育馆 | 生活区汇聚，双 10G 上核心 |
| 网络中心 / 数据中心 | 信息大楼（核心机房、数据中心机房） | 直连双核心 |

另设**出口 / DMZ 安全区**（R1/R2 + FW1/FW2 + DMZ 交换机）。

仿真收敛为代表性子集：教学、实验、宿舍、图书馆、生活、数据中心、DMZ 共 7 个业务区，外加 VLAN 90 管理网。

### Q2 奉贤校区和徐汇校区之间是否联网？

- **设计层面联网**：双出口路由器，R1 主用 CERNET，R2 备连梅陇校区并接 Internet；出校流量默认走 R1，R1 故障切 R2。
- **仿真层面未建该侧节点**：只保留 `internet`（203.0.113.0/24），跨校区链路属于「设计覆盖、仿真未建模」。
- 追问时补充：该链路在真实设备上可用静态路由或 BGP 落地，方案已预留互联网段与 BGP 配置章节口径。

### Q3 奉贤校区和外网之间是否联网？

联网。

| 要素 | 取值 |
| --- | --- |
| Internet 网段 | 203.0.113.0/24 |
| `internet` 节点 | 203.0.113.100 |
| 出口 VRRP VIP | 203.0.113.254（R1/R2） |
| Untrust 网段 | 10.90.1.0/24，防火墙 VIP .253，出口路由 VIP .254 |
| 出向转换 | 防火墙 `iifname eth1 oifname eth2` 做 masquerade |
| 入向发布 | DNAT `198.51.100.80:80/443 → 10.80.0.10` |

### Q4 是否全部能 Ping 通？

必须分两类回答：

1. **应当可达的**：CONN-01~10 全部通过
   - CONN-01 VLAN101 同网段互通
   - CONN-02 VLAN101 → VLAN102 三层互通
   - CONN-03 教学区 → 实验区 VLAN201
   - CONN-04 教学区 → 宿舍区 VLAN301
   - CONN-05 教学区 → 图书馆 VLAN50
   - CONN-06 教学区 → 生活区 VLAN61
   - CONN-07 教学区 → 数据中心 VLAN70
   - CONN-08 有线 → 无线 VLAN500
   - CONN-09 内网经 NAT 访问 Internet
   - CONN-10 内网访问 DMZ 服务器
2. **应当不可达的**：ISO 套件专门验证「不通」，这些不通才是正确结果
   - 宿舍 → 管理网 / 教学区 / 实验区 / 数据中心 阻断
   - 教学区 → 管理网 阻断
   - 宿舍 → 图书馆 默认拒绝
   - DMZ → 内网、外网 → Trust、外网 → 宿舍区 失败

结论表述：首次全量 **61/64** 通过，CONN、ROUTE、SEC、DHCP、NAT、LAG 全部通过；3 条失败（ISO-09、FAIL-04、FAIL-06）已定位根因并修复，关键路径复核通过；**修复后的 64 条全量回归未重跑**。

### Q5 设备选型如何？

按 14,514 个信息点、留 30% 余量的口径选型，不盲目堆高端型号。

| 类别 | 数量 | 选型口径 |
| --- | --- | --- |
| 核心交换机 | 2 | 框式/盒式三层，支持 VRRP/CSS |
| 区域汇聚 | 10 | 三层路由交换机，24–48×1G + 4–8×10G |
| 数据中心接入 | 2 | 24×10G，双上行核心 |
| 出口路由器 | 2 | NE40E 级别或 AR 系列，BGP/OSPF |

### Q7 有没有考虑无线网配置？

有。

- 架构：AC + 瘦 AP，数据本地转发，CAPWAP 只走管理流量；
- 子网：教学/图书馆/信息楼用 VLAN 500，宿舍/实验用 VLAN 510，与有线共用 DHCP 池；
- 数量：每栋每层 1 个 AP，合计 287 个；
- 认证：教学区 802.1X（教师）/ Portal（学生），宿舍区 802.1X + 漫游，生活区访客隔离；
- **边界**：仿真只验证 VLAN、地址池、策略逻辑，不模拟射频覆盖，射频需真实环境勘测，报告已作区分。

### Q9 有没有防火墙？

有，双机 fw1/fw2，使用 nftables 落地三区策略。

| 区域 | 连接 | 默认策略 |
| --- | --- | --- |
| Trust | 核心、全部校内 VLAN | 可访问 Untrust、DMZ |
| Untrust | Internet、梅陇校区 | 默认拒绝，仅放行命中 DNAT 的 80/443 |
| DMZ | Web、邮件、对外 DNS、VPN | 外网只可达指定端口，DMZ 不可主动访问内网 |

细节：
- DNAT：`198.51.100.80:80/443 → 10.80.0.10`，只允许 `ct status dnat` 流量；
- SNAT：仅 `iifname eth1 oifname eth2` 做 masquerade，避免改写 DNAT 回程；
- 管理口不对公网开放；
- SEC-01~06、NAT-01~07 全部通过。

### Q10 是否有双机备份？

| 层面 | 机制 | 验证 |
| --- | --- | --- |
| 核心 | 双核心 + VRRP（Trust VIP 10.0.100.253） | FAIL-01~03：停 core1 后 core2 接管，业务不中断，恢复后重新抢占 |
| 防火墙 | fw1/fw2 + VRRP（Trust VIP 10.0.100.254） | FAIL-05：停 fw1 后 fw2 接管 |
| 出口 | R1/R2 双出口 + VRRP | 设计中主备切换 |
| 链路 | 核心 `bond0` 802.3ad；服务器 `bond0` active-backup | LAG-07 拔成员业务不中断 |
| 汇聚 | 每区域双汇聚、双上行核心 | 设计冗余星型 |

**如实补充**：DHCP/DNS 所在的 `srv-dc1` 目前为单实例，`srv-dc2` 已建模但未承载服务；设计方案要求主备 2 台，这是仿真与设计的已知差距。

### Q12 是否考虑了网络的可扩展性、安全性、绿色环保？

**可扩展性**
- 区域汇总路由：核心只看见区域汇总，看不见单栋楼，减少路由表规模；
- 地址规划「地址即含义」：`10.A.B.0/24` 中 A 表示区域、B 表示楼栋，可平移扩展；
- IPv6 双栈预留，本期只规划 IPv4；
- 设备按 5–10 年、留 30% 余量选型。

**安全性**
- 出口三区防火墙 + NAT + 只开指定端口；
- 宿舍区细粒度 ACL：宿舍只能互访、DNS、Internet、DMZ 80/443，其余默认拒绝；
- 管理网独立 VLAN 90，业务区不可达；
- 802.1X / Portal + RADIUS，MAC/IP 绑定；
- DHCP Snooping、DAI、端口隔离、端口安全、未用端口 shutdown；
- 设备侧 SSH v2、SNMPv3、关闭 Telnet。

**绿色环保**
- 选高能效设备型号；
- PoE 按 AP 实际功率（约 15W/台）选型，宿舍百兆口不配 PoE+；
- 机房精密空调 + 冷热通道；
- 统一网管减少现场巡检能耗。

### Q13 其他特色

建议只讲以下三点，最不容易被追问倒：

1. **设计—实现可校验**：`configs/facts.json` 作为单一事实源，`tools/report_check.py` 逐键比对报告 facts 数据块，输出 `report check OK`，防止报告数字与工程脱节。
2. **自动化验收闭环**：8 个套件、64 条用例，退出码 0/1/2 区分「通过 / 用例失败 / 环境不可用」，结果落 JSONL + summary + 原始日志。
3. **补齐任务书易失分点**：DHCP 与 Relay、宿舍区隔离、DMZ 目的 NAT、LACP 链路聚合、VRRP 故障切换、可编辑拓扑图。
