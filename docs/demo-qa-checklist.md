## 1 开场：项目概况、系统细节与技术栈（约 2 分钟）

**讲：** 我们做的是奉贤校区校园网，覆盖教学、实验、宿舍、图书馆、生活和信息大楼六个区域，信息点约一万四千五百个。主干一万兆，从网络中心到各区域汇聚；汇聚到楼层一千兆；宿舍房间一百兆，其他房间一千兆。

**讲：** 架构是三层。信息大楼机房放两台核心交换机，两台之间用两条万兆线绑成一条；每个区域放两台汇聚，分别上联两台核心；接入交换机按楼宇放，每栋楼每一层一台。出口是两台路由加两台防火墙，防火墙分内网、外网和对外服务区三块，对外服务的网站单独挂在服务区。

**讲：** 全网划了十一个虚拟局域网，十个业务加一个管理，原则是一栋楼一个子网。预算按规模留三成余量，合计约六百八十七万。

**讲：** 技术栈这边，我们在一台苹果电脑上用容器化实验平台把整套网络跑起来：四十四台设备、六十六条链路。其中十四台是软件路由器和三层交换机，七台是二层交换机，两台用系统防火墙策略模拟硬件防火墙，其余是终端、服务器和传输桥。地址服务用轻量软件，链路聚合和虚拟网关用系统自带能力，配置由 Python 脚本一次生成。

```sh
open ../docs/topology.html
```

**演示：** 在网页上把“终端”和“接入”图层逐个点掉。

**说：** 剩下的就是骨干。左边两台红的是信息大楼机房的核心，蓝的是一教、1 号宿舍楼、实验一楼、图书馆、食堂这几处的区域汇聚，紫的是出口防火墙，橙的是出口路由。

## 2 实验一：教学区交换与无线（约 1 分钟）

**讲：** 一教每一层一台接入交换机，教室端口划在教学子网，无线单独一个子网。上联到一教的汇聚走 trunk，网关放在汇聚上，所以同一栋楼内是二层转发，跨楼才经过汇聚做三层转发。无线是统一控制器加瘦接入点，每栋楼每层一个，全校二百八十七个。

```sh
# 一教教室两台电脑互 ping
docker exec clab-campus-lab-pc-ta1 ping -c 2 10.10.0.12

# 一教有线电脑访问本楼无线接入点
docker exec clab-campus-lab-pc-ta1 ping -c 2 10.50.0.11
```

**说：** 同楼层通、跨楼层通、有线到无线也通，对应报告实验一的三条验收。

---

## 3 实验二：地址服务（约 1 分钟）

**讲：** 地址服务集中在信息大楼数据中心，一共八个动态地址池，教学、实验、宿舍、图书馆、生活区和两个无线各一个。十台区域汇聚做中继，把各楼的需求转给服务器。租期按区域区分：教学四小时，宿舍十二小时，其他八小时。下发的网关是虚拟地址，主备切换时电脑不用改配置。

```sh
# 一教演示电脑拿到的地址、网关、域名服务和租期
docker exec clab-campus-lab-pc-dyn1 cat /tmp/dhcp.env
```

**说：** 这台电脑拿到教学子网地址，网关是一教汇聚的虚拟地址，域名服务指向信息大楼，租期四小时。

## 4 实验三：冗余与出口安全（约 2 分钟）

**讲：** 冗余分四层。核心两台做虚拟网关，主用坏了备用接管；防火墙两台同样做虚拟网关；出口两台路由，一台主用教育网，一台备用运营商并兼连梅陇校区；链路层面，两台核心之间是双线聚合，数据中心服务器是双网卡主备。

**讲：** 出口安全统一收在防火墙上。内网出去做源地址转换，外面看到的是出口地址；外面进来只能访问对外服务区的网站，八十和四百四十三端口，内网地址外面碰不到。

```sh
# 看出口会话，内网源地址已被改写成防火墙外网口
docker exec clab-campus-lab-fw1 conntrack -L | grep 203.0.113.100 | head -3
```

```sh
# 先持续 ping 校外，再停掉信息大楼机房的主核心
docker exec clab-campus-lab-pc-dyn1 ping -c 30 -i 0.5 203.0.113.100 &
docker stop clab-campus-lab-core1
sleep 5
docker start clab-campus-lab-core1
```

**说：** ping 没断，备用核心接管了虚拟网关，恢复后主核心重新抢回。唯一单点是信息大楼那台地址与域名服务器，目前只有一台在跑，备机建了但没启用，这点我们如实说明。

---

## 5 实验四：路由与链路聚合（约 1 分钟）

**讲：** 内网跑开放最短路径优先协议，所有区域在一个骨干域里。核心向区域下发默认路由，区域只把汇总网段告诉核心，所以核心路由表不膨胀。两台核心之间的双线聚合成一条逻辑链路，带宽翻倍，一条线断业务不断。

```sh
# 一教电脑到校外的完整路径
docker exec clab-campus-lab-pc-dyn1 traceroute -n -w 1 -q 1 -m 8 203.0.113.100

# 核心邻居数量与聚合口状态
docker exec clab-campus-lab-core1 vtysh -c 'show ip ospf neighbor' | grep -c Full
docker exec clab-campus-lab-core1 cat /proc/net/bonding/bond0 | head -8
```

**说：** 从一教出去是五跳：楼层接入、一教汇聚、信息大楼核心、出口防火墙、出口路由，然后到校外。信息大楼核心看到十一条邻居，聚合口两条成员都在线。

## 6 实验五：区域隔离与自动化验收（约 2 分钟）

**讲：** 区域之间不经过防火墙，隔离做在区域汇聚上。宿舍六个方向全阻断：管理网、教学、实验、数据中心都进不去，只放行宿舍互访、域名服务、出网和对外服务区网站；生活区只放行出网和对外服务区，其他六个方向全拒绝；数据中心禁止主动出校；管理网只允许网管终端发起。

```sh
# 食堂电脑访问一教：应不通
docker exec clab-campus-lab-pc-life ping -c 2 -W 1 10.10.0.11

# 食堂电脑访问校外：应通
docker exec clab-campus-lab-pc-life ping -c 2 -W 1 203.0.113.100
```

**讲：** 验收是八个套件、六十四条用例，覆盖连通、路由、安全、地址服务、隔离、地址转换、链路聚合和故障切换。第一次跑了六十一分，三条失败定位到管理流量回程不对称和路由恢复等待窗口，修复以后全量六十四分全过，没有失败也没有跳过。测试开始前会先等核心把十一条邻居收齐，避免刚部署就判失败。

```sh
# 归档的全量结果：八套件、六十四分全过
cat tests/results/20261111T062929Z/summary.txt

# 报告数字与生成数据逐项核对，随后切回实验目录
cd .. && python3 tools/report_check.py
cd campus-lab
```

**说：** 这里看到八个套件全部通过，报告核对输出通过。现场不重跑全量，重跑大约两分钟。

## 8 边界与收束（约 1 分钟）

**讲：** 三点边界主动交代。第一，跨校区只做到设计层：出口备用路由兼连梅陇，也就是评委说的徐汇校区，仿真里没有建那头的设备。第二，文件传输服务本期没部署，对外服务区具备承载能力，列在后续工作。第三，地址和域名服务目前单实例。

**讲：** 无线这边仿真只验证了子网、地址池和认证策略，天线覆盖要到真实环境勘测；域名内外分设和八零二点一叉认证是设计内容，仿真没建模。

**说：** 一句话收尾：设计成体系、实现能跑通、结果可复核。
